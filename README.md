# 员工贺卡推送系统

在人事后台维护员工资料，使用公司统一底图叠加姓名、部门和祝福文案，审核后由飞书应用机器人私聊员工。先发送一条简短通知，发送成功后自动发送完整海报卡片；员工无需领取或确认。

默认采用固定底图，每次事件生成一张海报。生日与入职周年各有独立模板；不需要豆包密钥。

## 启动

需要 Python 3.10+。Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# 在编辑器中填写 .env，先保留 DRY_RUN=true
.\.venv\Scripts\python.exe run.py
```

访问 http://localhost:8848 。已有数据库启动时自动增量迁移，保留员工、事件、海报和推送流水。升级已有部署前应备份 data/app.db、config/templates.json 和 assets。

示例环境文件中的凭据留空；正式凭据填写在本机 .env。审核页面支持 ADMIN_TOKEN 管理口令。进程内调度器要求服务持续运行。

## 日常流程

1. **员工管理**：维护姓名、部门、工号、入职日期、出生年月、在职状态六项资料；下载同字段的空白 Excel 模板，也兼容旧 CSV/XLSX 导入。出生年月填写完整日期（年-月-日），操作列只在页面提供编辑入口。
2. **飞书自动对应**：保存、导入或同步后按唯一姓名关联当前应用的 open_id，员工页无需手动三重核验。同名或 ID 冲突会明确提示，不自动猜测；未连接飞书或连接失败不影响资料导入。发送前仍实时检查姓名、ID 及在职状态。
3. **文案与底图**：选择生日或周年模板，只维护祝福文案及字体、字号、加粗。右侧仅预览排版效果，无需选择员工或日期；生成时系统自动填入对应字段。「底图管理 → 上传 / 更换底图」可分别替换两类底图，支持 PNG/JPG/WebP（最大10MB）。新图等比适配原画布，可选居中裁切铺满或白色留边完整保留；上传后先预览，保存模板后用于新生成的海报，已有海报保持不变。
4. **海报审核**：表格支持按时间、类型、部门、状态筛选和日期排序。勾选后批量确认排期、重新生成或跳过；海报可放大，详细操作在弹窗内。立即推送仍须先确认。
5. **离职处理**：在员工列表多选后批量停用。系统保留历史记录，取消该员工未发送的任务；恢复在职不会恢复已取消任务。

页面只展示真实员工和事件；空库保持空表格。模板预览保留 {name}、{department}、{years}、{date} 等字段占位符进行实际渲染，不读取员工资料或填入虚构数据。导入模板只含表头。员工表格支持关键词、在职状态、部门、入职日期区间及出生月份区间筛选（首尾包含，月份支持跨年，如 11 月至次年 2 月），批量选择仅保留当前筛选内的记录。

操作提醒可逐条关闭或一键清空，每个页面最多保留最近5条。贺卡核查弹窗以员工资料、日期和审核操作为主，仅展示一张海报，点击小图查看大图，保留推送记录入口。旧记录保留已确认或已发送的海报；尚未关联图片时展示第一张可用海报，确认排期时自动关联当前预览图，无需选择方案。已关联海报不可用时要求重新生成，不以其他旧图替代。

员工资料和海报审核都支持按住左侧复选框或选择栏上下拖动，连续勾选多行；从已勾选行开始拖动则连续取消。拖动到列表边缘会自动滚动，按 Esc 可撤销本次拖选。也可先点起始行，再按住 Shift 点击末行（键盘支持 Shift + 空格），按当前筛选、排序选择区间。选中数量和批量操作即时更新，筛选隐藏的记录不参与操作。

员工资料勾选后，点击表格上方的「批量更正」。可在表格内逐人修改六项资料，或统一填写部门、入职日期、出生年月和在职状态；支持还原全部修改，保存按钮显示实际修改人数。每次最多更正1000人，仅提交改动字段；清空工号或日期表示删除该项原值。任一人员存在无效日期、工号冲突、同名更名冲突、正在推送或资料已被其他操作修改时，整批不保存并给出中文原因。保存成功后刷新列表，受影响的待发送海报需重新生成和审核。

推送审核表展示姓名、工号、部门、入职日期、生日、入职周年数、员工ID、飞书ID、推送状态、推送日期和异常提醒。入职周年数从入职日期自动计算，无需导入；审核表以该条贺卡日期为准，不使用生日年龄代替入职周年数。生日只有月日时不显示内部占位年份。员工资料页不展示或编辑邮箱、飞书 ID 和对应状态，历史数据仍保留。

审核页仅显示「待推送、已推送、推送失败」三个状态，默认筛选待推送；生成失败、对应受阻和过期停止归入推送失败，具体原因显示在异常提醒中。生成中、待确认、待重新生成、发送中、演练、跳过及回执不明归入待推送，说明中保留具体情况。只有已确认送达的记录显示已推送；演练不算真实发送，跳过的记录不会自动发送，回执不明也不能直接重试。推送日期分别标注计划时间与实际时间。异常列优先显示中文原因及处理建议，核查弹窗保留可展开的技术详情。回执不明不会当作未送达或提示直接重发。

## 导入及飞书对应规则

推荐从后台下载模板。中英文表头均可：

```text
姓名,部门,工号,入职日期,出生年月,在职状态
```

- 飞书 ID 指当前应用下的 **open_id**，不是 user_id、手机号或邮箱。
- 收件人按 **姓名 + 当前应用 open_id** 一一对应；确认排期、简短通知发送前及完整贺卡发送前都会读取飞书资料并检查授权通讯录中的同名冲突。姓名或 ID 不一致、ID 已属于其他本地员工、通讯录不完整时停止发送，不按相似姓名猜测。
- 通讯录按授权人员、部门（含下级部门）、用户组（含组内人员和部门）完整读取。范围含用户组时需开通 `contact:group:readonly`（读取用户组）并发布应用；缺少该权限时连接检查会明确提示，不能把漏读的名单当成完整名单用于自动对应。
- 确认排期会记录当前 App ID，消息流水保留姓名、open_id 和 App ID。切换应用或旧审核记录没有 App ID 时，需要重新生成并确认；读取名单或推送期间不允许修改应用配置，以免混用应用身份。
- 工号或 open_id 可以定位导入更新对象；姓名不用于自动覆盖。工号、open_id 指向不同员工，或现有姓名与导入信息冲突，拒绝该行。
- 同名不同部门可以新增；同名同部门且缺少可区分标识时要求人工核对。存在同名员工时不会建立姓名与 ID 对应，需先处理重名资料。
- 空单元格保留原资料；日期无效会逐行报错，不再静默清空。CSV 支持 UTF-8/GB18030，Excel 支持 XLSX 日期单元格，单次最多10000行、5MB。
- 日期支持 `2021-02-01`、`2021/2/1`、`2021年2月1日` 等常见写法，导入后统一保存为 `YYYY-MM-DD`。生日也支持 `2月29日` 这类仅月日写法；入职日期必须包含年份，不存在的日期仍会拒绝。
- 部门是业务资料，可按工号导入更新，不再参与飞书收件人核验；部门读取失败不影响唯一姓名与 ID 对应。
- 核验检查飞书在职状态。缺信息、权限不足、离职、冻结或核验不一致时阻止发送。
- 修改员工资料会撤销未发送海报的确认并使旧图失效。重新生成时使用新资料；若生日/入职日期已改变，跳过旧事件，重新扫描正确周期。
- 通讯录同步只补充空资料，不覆盖本地已录姓名、部门或生日，不因“此次没读到”推断离职，也不自动恢复已停用员工。只对飞书明确标记离职的用户停用；冲突逐项报告。

## 排版及底图

可用变量：

```text
{name} {department} {years} {company}
{date} {event_date} {year} {month} {day}
{join_date} {birth_date} {employee_id}
```

`{years}` 按当前设计显示中文数词；公司名称在模板设置修改。预览与正式生成使用同一套排版逻辑。

- 背景上传后先在编辑器预览，点保存才正式应用。新底图等比适配到当前模板画布，保留现有文字坐标。
- 系统内置 Noto 黑体、Noto 宋体（简体中文），随代码部署并附带 OFL 授权文件。「自动选择字体」优先使用内置字体，不依赖访问者电脑；海报由后台统一渲染。字体下拉框按内置、上传、项目和服务器字体分组；服务器仅列出识别到的常用中文字体。
- 「模板设计 → 上传字体」支持 TTF/OTF/TTC/OTC，最大32MB。上传后校验字体并应用到当前文案草稿，保存模板后用于新海报。字体集中存储在 assets/fonts/uploaded，所有后台管理员共用；此目录不提交 Git，部署迁移时应备份。上传不会安装到操作系统，也不会读取使用者电脑的字体目录。
- 段落自动换行；在设定区域内逐步缩小字号。到最小字号仍放不下会报错，阻止输出，避免静默裁字。
- 编辑器把旧模板的三段正文合并到单一文案模块，自动换行和跟随前文排版；后台保留五层配置格式兼容原合成流程。坐标、颜色等设计参数从界面收起。
- 正文工具栏支持整体左对齐、居中、右对齐，以及在光标处插入两个中文空格或空行。手动空格、首尾空行在保存和重新加载后保留。公司落款默认对齐正文区域的右边缘，并随正文高度下移。
- 模板配置原子保存，预览不会覆盖正式配置，各预览文件名独立。
- 保存新模板只影响之后生成的海报；已有确认的图片保持审核时版本。要应用新版，重新生成并再次审核。

配置保存在 config/templates.json。兼容保留原有 AI 生图模块，但默认关闭；固定底图模式始终生成一张图。

## 推送与异常处理

机器人按顺序自动发送两条消息：第一条是「你有一份专属祝福，完整贺卡即将送达」的简短通知，无图片和确认按钮；第一条接口返回成功后，自动发送第二条完整海报卡片。无需员工点击、回调订阅、长连接或公网海报链接。系统发送顺序固定，客户端的小窗弹出和通知展示由员工的飞书通知设置决定。

两条消息使用各自固定的请求标识，并保存独立回执。只有完整贺卡发送成功，审核状态才显示「已推送」。如果通知成功而海报明确失败，重试只发送海报；任一发送请求超时或结果不明时暂停重试，先核实飞书中的实际接收情况。推送记录区分通知送达与完整贺卡送达，演练模式不发送任何一条消息。重启后台后新推送使用此流程，已发送消息保持原样。

生日默认当天11:00，周年默认当天10:00；周四20:00扫描下周。时间使用 .env 的 TZ（默认 Asia/Shanghai）。2月29日在平年按2月28日处理；入职当年不触发周年。

| 状态 | 含义及处理 |
|---|---|
| generating | 正在生成，请等待 |
| ready | 待审核，查看海报并确认 |
| confirmed | 已确认，等待计划时间或手动立即推送 |
| pushing | 正在发送；不允许更改收件人或重复发送 |
| pushed | 已推送，保留流水，不允许再次投递 |
| simulated | 演练完成，未发送消息；正式发送前需重新生成、审核 |
| needs_regeneration | 资料或身份发生变化，重新生成并审核 |
| gen_failed | 排版或生成失败，修正后重新生成 |
| blocked | 身份或海报核验不通过，核对资料后重新审核 |
| failed | 推送明确失败；通知已送达时，重试仅补发完整贺卡 |
| delivery_unknown | 请求已发出但回执不确定；暂停重发，人工核实飞书和服务日志 |
| expired | 事件日期已过，停止自动及手动推送 |
| skipped | 已取消，不会自动恢复 |

发送前再次实时检查姓名、飞书 ID 和在职状态，使用生成时及确认时的员工快照校验海报。并发点击通过数据库事务只允许一条发送执行；飞书请求携带固定 UUID。自动重试仅处理确认过、仍在职、未过期、未达到次数上限且确定没有送达的失败事件。飞书明确拒绝的错误可在修正权限后重试。

启动时检查处理任务所属的进程。进程已退出的生成任务转为生成失败，可重新生成；未开始发消息的任务恢复为可重试失败；已经进入发消息阶段或缺少旧执行记录的任务转为回执不明并释放员工编辑锁。仍在运行的进程不会被接管。无法判断真实送达结果时，需管理员核实飞书消息与日志后处理。

`DRY_RUN=true` 不上传海报、不发送消息，流水标记演练，不记录为真实成功；身份核验仍访问飞书。完整的无网络测试请使用下面的测试命令。

## 飞书接入

使用企业自建应用，发布并开启机器人能力，让应用可用范围及通讯录授权覆盖目标员工。需要用户/部门读取、机器人发消息及上传图片的相关权限；缺权限时后台会报告无法核验。

在「员工资料 → 飞书连接」或「系统状态」填写 App ID 和 App Secret，点击「保存连接配置」后立即生效。密钥只写入本机已排除版本管理的 `.env`，接口不返回密钥；同一应用留空表示保留原密钥，更换 App ID 必须填写对应密钥。已有管理口令时配置与检查接口同样要求口令。

「检查通讯录连接」实际读取飞书通讯录授权范围，只有令牌有效且范围可读取才报告通过；员工姓名、ID 和在职信息在自动对应及发送时检查。连接或权限读取失败显示「暂无法核验」及飞书具体原因，身份不匹配显示「核验失败」，两者都不能放行推送。未配置应用凭据时不会伪造通过结果；open_id 属于具体应用，不能直接沿用另一个应用的 ID。

接口参考：[获取用户](https://open.feishu.cn/document/server-docs/contact-v3/user/get)、[获取部门](https://open.feishu.cn/document/server-docs/contact-v3/department/get)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)。

上线前应使用明确授权的测试账号验证应用权限和飞书客户端效果。2026-09-11 的走查与真实联调结果见 [系统走查与操作交接](docs/系统走查与操作交接-2026-09-11.md)。
