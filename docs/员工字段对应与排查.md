# 员工字段对应与排查

员工资料页展开「字段对应与检查」，查看当前后台连接的应用与本地已填人数；点击「检查飞书字段」读取当前应用授权范围内的资料。检查不写入员工、不生成海报、不推送消息。

| 后台字段 | 飞书来源 | 空值时检查 |
| --- | --- | --- |
| 姓名 | `name` | 用户基础信息与通讯录范围 |
| 部门 | `department_ids`，再读取部门名称 | 用户组织架构信息、部门读取权限和通讯录范围 |
| 工号 | `employee_no` | 受雇信息读取权限；企业是否填写工号 |
| 入职日期 | `join_time`，换算为日期 | 受雇信息读取权限；入职时间是否填写 |
| 生日（月日） | 可识别的生日/出生日期自定义字段 | 自定义字段定义、读取权限及员工字段值；无法提供时使用名单模板补全 |
| 在职状态 | `status.is_resigned` | 受雇信息读取权限；只有明确的离职状态才自动停用 |
| 用户 ID（open_id） | 当前应用返回的 `open_id` | 与姓名一一对应；不能用作工号，也不能跨应用混用 |

下载的空白 Excel 模板包含姓名、部门、工号、入职日期、生日（月日）、在职状态及用户 ID（open_id）。用户 ID 填当前应用的 `ou_…`，可在员工表格查看、搜索，在编辑窗口的「飞书用户对应」或批量更正表格中逐人更换。不能将同一个 ID 统一填给多人；保存后继续检查姓名与 ID 对应关系，不匹配时不会发送。旧六列模板仍兼容；导入或单人编辑留空 ID 保留原值，未绑定时连接飞书后自动对应。

本地人数只统计在职员工，飞书人数统计当前应用可读取的通讯录范围，两者不必相等。检查区不展示员工字段值，只展示汇总人数。

- **未返回字段**：接口没有提供该字段，检查权限和数据来源；不能仅凭这一项断言是权限问题。
- **值为空**：字段有返回但没有内容，检查飞书侧是否已填写。
- **格式无效**：字段存在但不能按当前规则转换，核对源数据格式。
- **读取失败**：例如有部门 ID，但无法读取部门名称，核对部门权限和授权范围。
- **无可读取的对应字段**：例如没有可识别的生日字段，先确认字段来源和开放设置。
- **未完成检查**：通讯录读取中断或被拒绝，结果保持未知，不把它显示为零人。

字段读取权限变化后，应按飞书平台要求发布并完成审批，再重新检查、同步。同步只补齐本地空白资料，保留手工填写的值；字段缺失不会以虚构值补齐。生日只按月日触发，不使用出生年份、不计算年龄；入职周年要求完整年月日且满一年。2 月 29 日只在实际有这一天的年份推送，不在平年替代到其他日期。缺少生日或入职日期的员工不会生成对应类型的贺卡。

## 在内网后台机器检查

代码需更新到实际运行服务的机器；开发电脑的 `127.0.0.1` 与内网机器使用各自的配置和数据库。仓库更新不会自动更新已运行的服务。

在后台项目目录、使用服务对应的 Python 环境运行：

```sh
python scripts/check_feishu_fields.py
```

脚本使用该机器既有的本地配置，输出应用 ID、字段来源和汇总计数，不输出 App Secret、管理口令、员工姓名、生日或 open_id 值。无需修改运行模式，也无需触发同步或推送。

检查接口和页面需重启后台后生效。更新前确认没有正在推送的任务，使用既有服务管理方式重启；保留内网机器的配置、数据库和上传资源，不用开发电脑的数据覆盖。
