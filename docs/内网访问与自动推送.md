# 内网访问与自动推送

管理人员访问公司运行电脑的固定地址，员工在飞书收到一条文字加横版封面的消息。点击文字、封面或卡片空白处，打开完整海报查看页；不再自动发送第二条长海报。封面使用项目现有生日、周年横版图片。整卡跳转使用飞书 `card_link`，封面关闭图片自身预览，避免只放大封面。

完整海报保存在内网。员工查看时也需要公司网络或 VPN；后台地址必须是员工设备能访问的地址。当前不要求公网入口、消息回调或将员工数据部署到外部服务器。飞书客户端决定网页窗口的呈现方式；这是内网海报查看页，并非客户端原生图片弹窗。

## 在实际运行后台的 Windows 电脑配置

例如后台在 `192.168.110.184`。在该电脑更新代码后，以管理员身份打开 PowerShell，在项目目录运行：

```powershell
.\scripts\enable_intranet.ps1 -Address 192.168.110.184 -Python .\.venv\Scripts\python.exe
```

`-Python` 使用这台电脑实际运行后台的 Python；没有虚拟环境时可使用 `python`。脚本校验地址属于当前电脑，备份本机 `.env`，配置 `HOST=0.0.0.0` 和 `POSTER_BASE_URL`，仅放行该内网地址 TCP 8848 端口的本地子网入站访问；不会关闭防火墙，不会改成正式发送模式，不覆盖人员资料。管理口令缺失时生成并保存在本机 `.env`，交给授权的后台使用人员，勿把飞书 App Secret 当成管理口令。

使用既有服务管理方式重启后台。其他人打开 `http://192.168.110.184:8848/`，页面提示登录时填写管理口令；不能在同事电脑使用 `127.0.0.1` 或 `0.0.0.0`。日常管理不需要在每位同事电脑安装程序。

只读查看监听情况：

```powershell
.\scripts\enable_intranet.ps1 -Address 192.168.110.184 -CheckOnly
```

同事电脑可运行 `Test-NetConnection 192.168.110.184 -Port 8848`。若后台电脑及部分电脑可以连接，而某些同事仍失败，需要公司 IT 放通这些办公子网/VPN 到后台地址和端口的访问；应用代码无法绕过 VLAN、访客 Wi-Fi 隔离或 VPN 路由。不要为此关闭整机防火墙或开放公网访问。

Linux 部署需使用同样的 `HOST`、管理口令和地址配置，由运维配置相应的内网入站规则；已有内部 HTTPS 域名可直接填入系统状态页。

## 自动推送与简单核查

系统每分钟扫描当天及未来七天的日期，生成海报并自动校对姓名、当前应用 open_id、在职状态和资料快照，到设定时刻发送。生日只匹配月日，周年按完整入职年月日计算。未来贺卡不会提前发送，过期日期不补发；停用员工、跳过记录、已发送记录和回执不明记录不会重新发送。

审核页可抽查图片、标记已核查、批量跳过和处理异常。“标记已核查”只做记录，不是发送前置条件。资料变化会重新生成有效日期内的海报；同名、ID 不一致、海报与资料不符仍停止推送。

“系统状态 → 内网访问与推送”保存可访问地址并开关自动推送。关闭自动推送会暂停定时生成及定时推送，仍允许授权管理员手动操作。`DRY_RUN=true` 始终为演练，不发真实消息。更新前已发完的记录不重发，已有旧版第一条通知回执的任务按原流程完成，避免重复通知。

每条新消息使用独立、不可猜测的海报链接，有效期 30 天，仅可读取该次推送的一张图，不能访问员工列表或管理接口；后台管理口令不进入链接。卡片禁用转发，但持有完整链接的人在公司网络内仍可查看这张海报，请按个人贺卡保管。员工停用、对应 ID 改变、重新生成或切换飞书应用会使旧链接失效。

仓库更新不等于内网服务自动更新。请在实际后台电脑保留原配置、数据库和上传资源，更新代码后重启，再进行同事设备访问验证和仅向指定测试收件人的消息验证。
