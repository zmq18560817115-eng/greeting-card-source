# 需求评估与修改说明

评估依据：当前源码及使用方描述，2026-09-10。目标流程是“维护员工 → 核验身份 → 统一底图排版 → 预览审核 → 飞书机器人私聊贺卡”。

### 使用方追加的界面调整

- 模板页收简为名单姓名称呼、一段祝福文案、字体字号及加粗。原多段文案自动合并；预览支持字段占位符与真实名单，保留统一底图替换入口。
- 审核与员工资料采用轻边框表格，提供关键词、部门、状态等筛选与多选批量操作；海报和详细信息在弹窗查看。
- 按使用方最新要求，移除演示入口和演示请求拦截，全部操作直接请求后端；空库保持空表。未选择员工的模板预览使用字段占位符。
- 公司落款默认右对齐；正文增加整体左对齐、居中、右对齐和插入空格/空行按钮。修复重载时裁掉首尾空白、强制恢复左对齐的问题。两类模板三种对齐均已实际渲染；保存后对齐位置及空白精确保留，24项模板回归通过。

此前的演示界面验证仅说明前端交互可用，不能代表真实飞书已接通。当前改为直接检查运行中服务的接口与页面按钮；正式员工列表仍为空，本地8848服务保持演练模式运行。

| 原有问题 | 影响 | 本次修改 |
|---|---|---|
| 导入按姓名兜底更新 | 同名员工互相覆盖 | 仅稳定标识定位更新；冲突逐行报告，禁止按姓名覆盖 |
| 部门子串匹配、直接填写ID即绑定 | 绑定错误收件人 | 姓名、完整部门名、应用open_id实时核验；候选选择仍需核验 |
| 停用只改员工状态 | 已排队消息仍可能发送 | 批量软停用并取消未发送事件，发送阶段再次检查 |
| 同步把未拉取到的人当作离职 | 授权范围变化导致误停用 | 仅处理飞书明确的离职状态，不根据缺失推断 |
| 文案只能修改文字 | 无法适配公司底图 | 字体、字号、颜色、位置、宽高、换行、行距、对齐、自动排版可配置 |
| 默认多张候选但底图相同 | 重复生成，审核步骤冗余 | 固定底图只生成一张海报 |
| 字体引用文件未随源码提供 | 合成失败或字体不确定 | 默认auto及可用字体枚举，明确检查指定字体 |
| 段落高度与边界缺少完整校验 | 文字重叠或裁切 | 换行、缩小字号、宽高及画布边界检查，容纳失败阻止输出 |
| 预览上下文字段不足 | 部门、生日等变量报错 | 完整变量及真实员工预览，独立输出文件 |
| 员工改名/调部门后旧图仍能发送 | 文案与收件人资料不一致 | 生成/确认快照，资料变动使旧图失效，异步结果不能复活旧图 |
| 强制推送绕过审核、并发重复发送 | 未审核海报或重复通知 | 立即推送只绕过时间，必须已审核；事务抢占与UUID保护 |
| 演练标记真实推送成功 | 无法区分验收与生产 | 独立演练状态及流水，不记真实送达时间 |
| 网络超时直接重试 | 实际已送达时收到重复消息 | 回执不明单独暂停，保留人工核实入口信息 |
| 服务中断后任务一直处理中 | 无法重试或管理员工 | 保存执行进程和发送阶段，启动时恢复已中断任务 |
| 先扫描再生成遗漏旧事件 | 已扫描海报一直等待 | 周期生成纳入已扫描但尚未生成及生成失败的事件 |
| 旧排期无发送期限 | 重启后发出过期祝福 | 超过事件当日停止发送，保留过期状态 |
| 环境示例内包含硬编码凭据 | 示例传播会携带密钥 | 示例改为留空，默认演练；原凭据如仍有效应由持有人更换 |

## 业务决策

- 保留现有生日/入职周年场景和排期规则。没有自行扩展节日、群发或其他事件类型。
- 删除离职员工采用软停用，保留历史推送及审核证据。批量操作前展示选中人员并由管理员操作。
- 多部门员工采用“至少一个完整部门名精确相同”，不做模糊匹配；飞书部门信息读取失败则核验不通过。
- 同名同部门的不同员工仍须管理员录入各自正确open_id；三项核验不能代替源名单的正确性。
- 配置保存影响后续生成，不悄悄修改已审核海报。应用新版设计需要重新生成和确认。
- 推送中的本地员工资料暂时禁止修改；发送状态不明时暂停重发，避免凭猜测重复通知。

## 验收与部署边界

本次验证：116项离线测试全部通过；Python编译、前端JavaScript语法检查和启动迁移/任务恢复检查通过。浏览器使用临时员工库验证新增员工、模板加载、模板切换及真实员工预览；两类1080×2340海报已渲染并检查文字可读性。测试服务已关闭。

本地测试覆盖业务规则、API和合成逻辑；使用临时数据库及模拟飞书，不触达真实员工。浏览器检查针对后台页面和本地预览。真实飞书权限、企业通讯录返回及移动客户端点击效果需要由已授权测试员工在部署环境验收。

当前源码已接续GitHub仓库main分支的原有历史，纳入Git版本管理。员工数据库、生成海报、日志、本机环境文件不纳入提交；示例导入文件仅保留表头，旧调试脚本的测试联系方式改从环境变量读取。启动会增量补充数据库列，不删除已有业务数据。部署前备份数据库与模板；参见README中的运行命令。
